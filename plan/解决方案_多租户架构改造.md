## 1. 目标架构总览

### 总体架构

```
                        公网访问
                            │
                      natapp tunnel
                     (映射到 80/443)
                            │
                       ┌────┴─────┐
                       │  Nginx   │  ← 统一网关
                       │  反代网关 │
                       └────┬─────┘
                            │
         ┌──────────────────┼──────────────────┐
         │                  │                  │
   / → admin:51668    /visitor/* →        /api/* →
   (React 管理端)     visitor_flask:51670   FastAPI 后端
                      (访客端)              (51666)
```

**一句话**：一个域名 + 一个端口（80/443），Nginx 根据路径分流，natapp 只需映射到 Nginx 端口。

| 路径 | 目标服务 | 用途 |
|------|---------|------|
| `/` | admin React (51668) | 管理后台（普通用户+超级管理员）|
| `/visitor/?user_id=xxx` | visitor Flask (51670) | 访客端 |
| `/api/*` | FastAPI backend (51666) | 后端 API |

## 2. 用户角色与权限

### 角色定义

| 角色 | 权限 | 说明 |
|------|------|------|
| **超级管理员** (super_admin) | 用户管理、系统级 Key 配置、提示词管理、全用户用量总览、 即当前 admin 账号升级 |
| **普通用户** (user) | 自己的知识库、简历、面试管理、Agent 对话、访客端开关和口令 | 新注册用户，LLM/搜索 Key 用系统默认，不涉及 Key 和提示词管理 |

### admin/admin123 账号处理

```
当前环境（你的服务器）:
  └── 手动跑迁移脚本 → admin 升级为 super_admin，所有配置数据保留

开源给别人的代码:
  └── 全新部署，无迁移脚本，首次注册的账号自动成为 super_admin
```

> ⚠️ **数据迁移是一次性的本地脚本，不塞进应用代码。** 开源后别人下载的是干净的多租户代码，不会有你的数据。

### 3.3 获取当前用户 — 依赖注入

```python
# routers/deps.py
from fastapi import Depends, HTTPException
from fastapi.security import HTTPBearer
from sqlalchemy.orm import Session
from services.database import get_db
from services.models import User
import jwt

security = HTTPBearer(auto_error=False)

def get_current_user(
    credentials = Depends(security),
    db: Session = Depends(get_db)
) -> User:
    if credentials is None:
        raise HTTPException(status_code=401, detail="未登录")
    try:
        payload = jwt.decode(
            credentials.credentials,
            settings.SECRET_KEY,
            algorithms=["HS256"]
        )
        user = db.query(User).filter(User.id == payload["user_id"]).first()
        if not user or not user.is_active:
            raise HTTPException(status_code=401, detail="用户不存在或已禁用")
        return user
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail="Token 已过期")

def require_super_admin(user: User = Depends(get_current_user)):
    if user.role != "super_admin":
        raise HTTPException(status_code=403, detail="需要超级管理员权限")
    return user
```

## 5. 认证与用户系统

### 5.1 注册

```python
# POST /api/auth/register
{ "username": "xxx", "email": "xxx", "password": "xxx", "captcha_token": "xxx" }
```

- 用户名 + 邮箱 + 密码（bcrypt 哈希）
- **滑块验证码**防止机器注册
- 成功后返回 JWT，自动跳转到 Agent 引导页
- 首次注册的用户自动成为 `super_admin`（后续注册都是 `user`）

### 5.2 登录

```python
# POST /api/auth/login
{ "login": "username 或 email", "password": "xxx" }
# → { "token": "jwt...", "role": "super_admin|user" }
```

**登录后前端行为：**
- `role === "super_admin"` → 侧边栏多出「用户管理」「用量总览」「系统配置」
- `role === "user"` → 完全保持当前 Admin 界面不变
- 两者都保留自己的 Agent、简历、知识库等功能

### 5.3 JWT 结构

```python
{
    "user_id": "uuid",
    "role": "user",
    "exp": 7天后
}
```

### 5.4 现有登录改造

当前 `admin.py` 的登录端点改成查 `users` 表，不再比对 `ADMIN_PASSWORD` 环境变量。迁移后的 admin 账号从 users 表验证。

```python
def generate_faq_answers(user_id: str) -> list:
    """根据用户知识库内容，用 LLM 生成 FAQ 答案"""
    kb = KnowledgeManager(user_id).read_knowledge()
    
    # 标准问题模板（来自 06_HR高频问答库.md 的 questions）
    questions = [

        "核心优势是什么",
        "离职原因是什么",
        "为什么选择我们公司",
        # ...
    ]
    
    results = []
    for q in questions:
        answer = llm.invoke(f"""
        基于以下知识库内容，用第一人称"我"回答HR的问题。
        回答要自然真诚，有具体细节，不要编造知识库中没有的信息。
        
        知识库：
        {kb}
        
        HR问：{q}
        """)
        results.append({"question": q, "answer": answer})
    
    return results
```

## 13. 当前用户数据迁移

### 13.1 迁移脚本（本地手动执行）

```python
# scripts/migrate_single_to_multi.py
"""
单用户 → 多租户数据迁移脚本。
在你的服务器上手动跑一次，不包含在开源代码中。
"""

import sqlite3
import uuid
import bcrypt
import json
import os
from datetime import datetime

BACKEND_DIR = os.path.dirname(os.path.dirname(__file__))
DB_PATH = os.path.join(BACKEND_DIR, "hr-agent", "backend", "data", "app.db")
ENV_PATH = os.path.join(BACKEND_DIR, ".env")

def migrate():
    # 1. 备份数据库
    bak_path = DB_PATH + ".bak"
    if not os.path.exists(bak_path):
        import shutil
        shutil.copy2(DB_PATH, bak_path)
        print(f"✓ 已备份到 {bak_path}")
    
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    
    # 2. 检查是否已迁移
    existing = conn.execute(
        "SELECT name FROM sqlite_master WHERE type='table' AND name='users'"
    ).fetchone()
    if existing:
        print("✓ 已迁移，跳过")
        return
    
    # 3. 创建 users 表
    conn.executescript("""
        CREATE TABLE users (
            id VARCHAR PRIMARY KEY,
            username VARCHAR UNIQUE NOT NULL,
            email VARCHAR UNIQUE NOT NULL,
            password_hash VARCHAR NOT NULL,
            role VARCHAR DEFAULT 'user',
            is_active BOOLEAN DEFAULT TRUE,
            created_at DATETIME DEFAULT CURRENT_TIMESTAMP
        );
    """)
    print("✓ 已创建 users 表")
    
    # 4. 从 .env 读取 admin 密码
    admin_password = os.environ.get("ADMIN_PASSWORD", "admin123")
    hashed = bcrypt.hashpw(admin_password.encode(), bcrypt.gensalt()).decode()
    admin_id = str(uuid.uuid4())
    
    conn.execute(
        "INSERT INTO users (id, username, email, password_hash, role) VALUES (?, ?, ?, ?, ?)",
        (admin_id, "admin", "admin@local", hashed, "super_admin")
    )
    print(f"✓ 已创建超级管理员账号 (admin)")
    
    # 5. 创建 user_configs 表
    conn.executescript("""
        CREATE TABLE user_configs (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            user_id VARCHAR NOT NULL REFERENCES users(id),
            config_key VARCHAR NOT NULL,
            config_value TEXT,
            updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
            UNIQUE(user_id, config_key)
        );
    """)
    
    # 6. 迁移 knowledge_base → 加 user_id
    conn.executescript("""
        CREATE TABLE knowledge_base_new (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            user_id VARCHAR NOT NULL,
            category VARCHAR NOT NULL,
            data TEXT,
            updated_at DATETIME,
            UNIQUE(user_id, category)
        );
        INSERT INTO knowledge_base_new (id, user_id, category, data, updated_at)
        SELECT id, ?, category, data, updated_at FROM knowledge_base;
        DROP TABLE knowledge_base;
        ALTER TABLE knowledge_base_new RENAME TO knowledge_base;
    """, [admin_id])
    print("✓ 已迁移 knowledge_base 数据")
    
    # 7. 迁移其他表（resumes, agent_conversations 等）
    tables_to_migrate = [
        "resumes", "agent_conversations", "conversations",
        "sessions", "interview_guides", "crawled_jobs", "stats"
    ]
    for table in tables_to_migrate:
        # 检查列是否存在
        cols = [c["name"] for c in conn.execute(f"PRAGMA table_info({table})").fetchall()]
        if "user_id" not in cols:
            conn.execute(f"ALTER TABLE {table} ADD COLUMN user_id VARCHAR DEFAULT '{admin_id}'")
        print(f"✓ 已迁移 {table}")
    
    # 8. 迁移 applicant_profile（原 id=1 → 改为 user_id 关联）
    existing_profile = conn.execute("SELECT * FROM applicant_profile WHERE id=1").fetchone()
    if existing_profile:
        conn.execute("UPDATE applicant_profile SET id=? WHERE id=1", (admin_id,))
        # 实际上应该改为 user_id 列...
        # 简化处理：加 user_id 列
        cols = [c["name"] for c in conn.execute("PRAGMA table_info(applicant_profile)").fetchall()]
        if "user_id" not in cols:
            conn.execute(f"ALTER TABLE applicant_profile ADD COLUMN user_id VARCHAR DEFAULT '{admin_id}'")
    
    # 9. 迁移知识库文件
    old_kb_dir = os.path.join(BACKEND_DIR, "hr-agent", "backend", "knowledge")
    new_kb_dir = os.path.join(BACKEND_DIR, "hr-agent", "backend", "user_data", admin_id, "knowledge")
    if os.path.exists(old_kb_dir):
        os.makedirs(new_kb_dir, exist_ok=True)
        import shutil
        for f in os.listdir(old_kb_dir):
            if f.endswith('.md'):
                shutil.copy2(os.path.join(old_kb_dir, f), os.path.join(new_kb_dir, f))
        print(f"✓ 已迁移知识库文件到 {new_kb_dir}")
    
    conn.commit()
    conn.close()
    print("✓ 迁移完成！")
    
    # 10. 创建 user_data 目录结构
    print("\n请确认：")
    print(f"  super_admin ID: {admin_id}")
    print("  username: admin")
    print("  password: (保持 .env 中的 ADMIN_PASSWORD)")

if __name__ == "__main__":
    migrate()
```

## 16. 附录知识库隔离

### 16.1 问题

附录知识库（appendix）是独立于主知识库的另一套机制，目前完全全局共享：

| 组件 | 现状 | 问题 |
|------|------|------|
| `add_appendix_to_store()` | 向量存到 `settings.VECTOR_STORE_DIR`（全局） | 所有用户的附录混在一个向量库 |
| `get_appendix_info()` | 读全局向量库 | 返回所有用户的附录总量 |
| `remove_by_ids()` | 删全局向量库 | 不区分用户 |
| `_load_appendix_records` | `KnowledgeBase.category=="appendix_records"` 无 user_id 过滤 | records 全用户共享 |
| `_save_appendix_records` | 同上 | records 全用户共享 |
| `APPENDIX_STORAGE_DIR` | 全局路径 `data/appendix_uploads/` | 上传文件不区分用户 |
| 所有 `appendix/*` 端点 | 无 `user_id` 注入 | 任何人都能查看/操作 |

## 总结

这次改造的核心目标：

1. **数据隔离** — 每个用户有自己的知识库、简历、配置
2. **角色分离** — super_admin 管全局，user 管自己的
3. **向后兼容** — 你的 admin 账号和数据完全保留
4. **最小侵入** — 保持现有功能不变，只加隔离层和适配层
5. **开源友好** — 别人下载后直接注册可用，无需迁移脚本
